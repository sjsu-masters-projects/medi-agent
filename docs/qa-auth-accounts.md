# QA Auth Accounts

Use real environment-specific accounts created through the normal signup flows. Do not commit live credentials to the repo.

## Required Accounts

Create one account for each shared QA environment:

- `Patient QA account`
- `Clinic Admin QA account`
- `Clinician QA account` (non-admin)

## Patient Account Checklist

1. Sign up through the patient portal `/signup`
2. Complete onboarding
3. Keep the account usable for:
   - login verification
   - onboarding verification
   - document upload verification
   - invite-code join verification

## Clinic Admin Account Checklist

1. Sign up through the clinician portal `/signup`
2. Use the clinic-admin bootstrap flow when creating a fresh clinic: `/signup/admin`
3. Verify clinic profile fields are populated
4. Enroll MFA through `/settings/mfa`
5. Keep the account usable for:
   - clinic-code verification before login
   - login verification
   - MFA setup and MFA login verification
   - clinic-wide invite-code visibility
   - verifying `Generated by ...` provenance on invite history

## Clinician Account Checklist

1. Sign up through the clinician portal `/signup`
2. Verify clinic profile fields are populated
3. Enroll MFA through `/settings/mfa` when the environment expects clinician MFA coverage
4. Keep the account usable for:
   - login verification
   - MFA login verification
   - dashboard access verification
   - invite-code generation
   - patient linking workflows
   - verifying personal-only invite visibility (no clinic-wide admin view)

## Linking the Accounts

1. Sign in as the clinic admin QA user or clinician QA user
2. Generate an invite code
3. Sign in as the patient QA user
4. Join the clinician with that invite code during onboarding or later through the patient flow
5. If admin and clinician accounts share a clinic, verify:
   - admin sees clinic-wide invite history
   - non-admin clinician sees only their own codes

## Credential Sharing

- Share credentials with teammates out-of-band only
- Never place live passwords in the repo, screenshots, or committed environment files
- If a password changes, notify teammates in the same out-of-band channel

## Reset / Recovery

- If the patient account drifts, recreate it through the patient signup flow
- If the clinic admin account drifts, recreate it through `/signup/admin` or assign a new admin in the same clinic
- If the clinician account drifts, recreate it through the clinician signup flow
- Re-link the accounts with a fresh invite code after recreation

## Minimum QA Coverage

Before closing auth-related work in a shared environment, verify:

1. Clinic code can be resolved before clinician login
2. Clinic admin can sign in and complete MFA
3. Non-admin clinician can sign in and complete MFA
4. Patient can join with a fresh invite code
5. Admin invite history shows code provenance
6. Non-admin clinician invite history stays limited to their own codes
