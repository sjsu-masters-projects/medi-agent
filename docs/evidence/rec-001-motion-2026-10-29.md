# REC-001-MO — Records motion and state feedback

Local follow-up on `fix/patient-records-clarity`, October 29, 2026.
[Scope](../../.agent/specs/rec-001-patient-record-clarity.md#records-motion-and-state-feedback--october-29-follow-up).
Implementation and local checks only: no commit, push, merge, deployment, database
change or API change.

## Decisions

- Timings come from the UX-002 handoff motion map. The animated reference linked
  from `DESIGN_SYSTEM.md` renders client-side; a fetch returned no readable content,
  so it was not compared frame by frame.
- Polling checks each processing document, reusing the existing 3s→30s backoff. It
  pauses while the tab is hidden and stops after 10 minutes of visible checking. One
  request per processing document was accepted because patients rarely have more than
  one or two at once.
- The explanation "taking longer" note appears at 15 seconds, the chat slow-turn
  threshold. The explanation workload budget is 20 seconds per attempt with a fallback
  route (`backend/src/app/adk/registry.py`).
- The finished-processing highlight and the removal notice use neutral tokens, so
  neither can read as clinical approval (Records override in `DESIGN_SYSTEM.md`).
- Patients have no processing-retry endpoint, so the parse-failure action is
  labelled **Upload another**, not **Try again**.
