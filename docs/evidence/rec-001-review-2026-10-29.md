October 29, 2026, branch `fix/patient-records-clarity`. Scope: record clarity,

## Review findings resolved

- Reopening a ready record used to request a fresh model presentation. Migration
  102 and `DocumentPresentationService` now persist validated presentations per
  document/locale, exact stored-summary hash and format version. Ownership/existence
  is checked before every cache read. Misses generate through the existing bounded
  workload; failed/unverified output is not saved. Pending work survives a closed
  viewer and is shared within an API process. Separate replicas can still generate
  independently on simultaneous cold misses. First-time generation latency has not
  been measured live.
- Polling stopped at completed extraction even while the stored summary was pending.
  It now watches that explicit lifecycle to completion, failure or the existing
  timeout, and starts explanation presentation once the summary arrives.
- An older list read could replace a newer refresh, and account changes could retain
  the prior Records workspace. Superseded responses are ignored and the workspace
  is keyed by account. Singular record counts are grammatical in both locales.
- Background polling renewed source URLs and could restart a preview while the
  patient read it. It now retains already-available URLs; explicit Refresh renews
  them. The pending-summary test verifies the original download remains stable.

Also reviewed: review status stays separate from uploader, parsing and AI content;
pending/failed/stale explanations cannot reach speech/chat; source removal is
limited to the patient's own pending unused upload and rechecked transactionally;
refusals preserve clinical/source history, successful removals retain minimal audit,
and correction requests require recipient choice, draft preparation and normal Send.
No automatic message or chart change was introduced. Shared modal/pull-to-refresh
changes are opt-in; focus, exit/reopen, reduced motion and error recovery have tests.
