## Findings resolved

- Missing ADR follow-up metadata previously implied testimony was given outside a
  request, while differing request identifiers implied an earlier request. Labels
  now distinguish unrecorded linkage, this follow-up and another follow-up without
  inventing chronology.
- The timeline's value-pattern heuristic also changed filenames and medicine names
  containing dots/underscores. Only explicitly known code fields are humanized;
  source values remain exact in both the preview and record details.
- Duplicate copy assumed the patient uploaded the file. It now describes the
  duplicate independently of uploader. An absent extraction no longer claims the
  original document has no details.
- Flattening multi-field symptom context lost the distinction between results,
  units, reference ranges, doses and dates. Those fields now keep readable localized
  labels; a single amount remains concise beneath the fact-type label.
- Generic conflict text no longer claims another person changed the record.
  Server-failure details are masked for every response shape, including validation
  arrays, while error status/code handling remains unchanged.
- A document-row link no longer promises to open a cited page. Its cited page is
  displayed separately; direct page navigation remains deferred.
- Removed a duplicate comment and corrected row indentation. Chat date formatting
  reuses its calendar formatter within a call instead of rebuilding it per lookup.

Added/extended meaningful regression coverage for preserved source values,
unrecorded follow-up linkage, duplicate upload origin in both locales, labelled
multi-value symptom context and array-shaped server failures. Existing behavioral
tests cover the remaining wording, technical-detail placement and saved-zone dates.

## Impact and remaining acceptance

Patients and clinicians see plain labels, shorter message metadata, friendly time
zones and less repeated text. Original ids, versions and raw imported data remain
accessible in technical disclosures where provided. Unexpected clinician errors
may now show a general action/retry message rather than developer details. Patient
chat day boundaries and display times follow the saved zone when usable, with the
device-zone fallback retained; no stored timestamp or appointment time is rewritten.

Correction requests use title, added date when known and original filename instead
of a database id in the prepared text. They still require recipient selection and
Send; a structured record attachment/link remains deferred, so similarly named
records can need clarification. Source navigation still opens the document row,
not the cited page itself. No AI request, approval, data-access or chart-write
behavior is added by these changes.
